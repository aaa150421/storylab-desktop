# 이야기공방 — 자동 업데이트 지원 프로젝트

이 프로젝트는 `storylab.html`을 Electron 데스크톱 앱으로 실행하며, **설치형 Windows 앱(NSIS)** 에 자동 업데이트 기능을 추가한 버전입니다.

## 먼저 알아둘 점

- 이 프로젝트의 자동 업데이트는 GitHub Releases를 통해 새 설치 파일과 업데이트 메타데이터를 배포하는 방식입니다.
- 아래 설정을 완료하고 자동 업데이트 지원 버전(현재 프로젝트 버전 `1.0.1`)을 한 번 설치해야, 그 다음 버전부터 자동 업데이트를 받을 수 있습니다.
- 자동 업데이트는 **설치형 Setup EXE** 에서 지원합니다. 포터블 EXE는 자동 업데이트 대상이 아닙니다.
- 업데이트를 설치해도 Electron 앱의 사용자 데이터 폴더는 보통 유지되지만, 중요한 원고는 업데이트 전에 앱 안의 백업 기능으로 JSON 파일을 따로 저장하세요.

## 1. GitHub 저장소 만들기

1. GitHub 계정이 없다면 https://github.com 에서 계정을 만듭니다.
2. 새 저장소를 만듭니다. 예시 이름은 `storylab-desktop`입니다.
3. 이 프로젝트 파일을 해당 저장소에 올립니다.

## 2. 저장소 이름 설정하기

`package.json` 파일에서 아래 두 곳의 `YOUR_GITHUB_USERNAME`을 본인의 GitHub 사용자 이름으로 바꿉니다. 저장소 이름을 다르게 만들었다면 `storylab-desktop`도 실제 저장소 이름으로 바꿉니다.

- `repository.url`
- `build.publish` 안의 `owner`와 `repo`

두 설정이 실제 GitHub 저장소와 정확히 일치해야 합니다.

## 3. 자동 업데이트가 포함된 첫 설치 파일 만들기

Windows 명령 프롬프트에서 프로젝트 폴더를 열고 실행합니다.

```bat
npm.cmd install
npm.cmd run dist:win
```

`dist` 폴더에 생성된 `이야기공방 Setup 1.0.1.exe`를 실행해 설치합니다. 이미 설치한 이전 버전이 있다면, 원고를 백업한 뒤 이 새 설치 파일로 업데이트 지원 버전을 설치하세요.

## 4. 다음 버전 배포하기

새 기능을 `storylab.html` 또는 앱 코드에 반영한 뒤 `package.json`의 `version`을 올립니다. 예를 들어 `1.0.1`에서 `1.0.2`로 변경합니다.

그 다음 프로젝트를 GitHub 저장소에 올리고, 새 버전 태그를 푸시합니다. 예를 들어 버전이 `1.0.2`라면 Git 저장소에서 다음처럼 실행합니다.

```bash
git add .
git commit -m "이야기공방 1.0.2 업데이트"
git push
git tag v1.0.2
git push origin v1.0.2
```

태그를 푸시하면 `.github/workflows/release.yml`이 실행되어 Windows 설치 파일을 만들고 GitHub Releases에 게시합니다. GitHub 저장소의 **Actions** 탭에서 작업이 성공했는지 확인하세요.

> 위 명령의 `git`을 사용하려면 Git이 설치되어 있고 프로젝트가 GitHub 저장소와 연결되어 있어야 합니다. Git을 아직 사용하지 않는다면 먼저 저장소 설정을 완료해야 합니다.

## 5. 사용자가 업데이트 받는 방법

앱은 실행 후 약 8초 뒤 업데이트를 확인하고, 이후 6시간마다 확인합니다. 새 버전이 게시되어 있으면 자동으로 다운로드하며, 다운로드가 끝나면 다시 시작해 설치할지 묻습니다. 인터넷이 없거나 업데이트 서버에 접속할 수 없을 때는 앱을 계속 사용할 수 있습니다.

## 빌드 설정 참고

- 설치형 자동 업데이트는 `electron-updater`와 `electron-builder`의 GitHub Releases 게시 설정을 사용합니다.
- GitHub Actions는 태그 `v*`가 푸시될 때 실행됩니다.
- `package.json` 버전과 태그 버전을 반드시 일치시키세요. 같은 버전 번호를 재사용하지 마세요.
- 현재 ZIP에는 GitHub 사용자 이름과 저장소 이름이 예시 값으로 남아 있으므로, 실제 저장소를 만들고 해당 값을 변경하기 전에는 게시/자동 업데이트가 작동하지 않습니다.
- EXE는 사용자의 Windows PC에서 빌드하고 실제 설치/업데이트를 테스트해야 합니다. 이 환경에서는 Windows 바이너리를 직접 실행해 검증하지 않았습니다.
